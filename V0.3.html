Detail NiveauLevel of Detail c

IRI https://w3id.org/utt/def/DetailNiveau
Description

  • Top concept of the UTT level of detail SKOS vocabulary, Each concept carries two alignments: the CityGML LoD concept, and the data quality levels D, C, B, A and A+ used by the COB Trial Trench Database. The COB levels are the scale the Dutch sector already applies when accepting historic records, so aligning to them lets a UTT record be graded without a separate assessment. Neither CityGML nor the COB scheme has a normative OWL publication, so both alignments are expressed as scope notes.

  • Detailniveau van vastgelegde geometrie.

  • Level of detail of captured geometry.
See Also https://www.ogc.org/standards/citygml

UTT DatasetUTT Dataset c

IRI https://w3id.org/utt/def/UTTDataset
Description

  • A published collection of UTT trench records held by one party. Each participating organisation publishes a description of its own dataset stating the endpoint that serves it, the licence, the spatial and temporal extent, and a contact point. This description layer is what makes the architecture federated in fact rather than in name: a query planner can locate the relevant endpoints without any central store holding the underlying records.

  • Een gepubliceerde verzameling UTT proefsleufgegevens van één partij, met beschrijving van endpoint, licentie en dekking.

  • A published collection of UTT trench records held by one party, described by endpoint, licence and coverage.

ObservationWaarneming c

IRI https://w3id.org/utt/def/Waarneming
Description

  • A record of a cable or pipe observed in a test trench, including its verified position. Links to the registered asset via komtOvereenMet when identifiable. uniteenheid ap

IRI https://w3id.org/utt/def/eenheid
Description

Declares the unit in which values of the annotated datatype property are expressed. Values are QUDT unit individuals, so the unit itself is identified by a QUDT IRI and is machine resolvable.

A local annotation property is used rather than a QUDT predicate for two reasons. First,
qudt:unit is deprecated in QUDT 2.1 and marked dcterms:isReplacedBy qudt:hasUnit. Second,
qudt:hasUnit relates a system of units to a unit, which is a different relationship from
the one needed here. QUDT provides no predicate for annotating an owl:DatatypeProperty
with the unit its values carry, because QUDT expects measurements to be reified as
qudt:QuantityValue instances.

UTT deliberately records plain xsd:decimal values rather than reified quantity values,
since contractors supply flat numeric fields and reification would add a node per
measurement for no practical gain. This property states the expected unit for producers
and consumers of that data. It is documentation, not a quantity construction, and no
reasoner will derive unit conversion from it.
